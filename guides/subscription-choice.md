# 套餐选择：Coding Plan 还是 Token Plan

> **本文件永不进入模型上下文**，只给人读。
> 理由：这是个一次性决策，不是每任务决策。把它写进规则，等于让每轮对话都为一次性的选择付 token。

## 一、两种套餐是什么

**Coding Plan（编程工具专用包月）**

- 形态：固定月费，专供 Claude Code / Cursor / Codex 等编程客户端
- 优点：单价低，重度使用非常划算
- 代价：**锁定工具，通常也锁定厂商**

**Token Plan（通用额度，按量计费）**

- 形态：充值额度，按 token 消耗扣费
- 优点：通用 —— 能跑脚本、批处理、自建应用、跨厂商对比
- 代价：单价高，用量不可预测

## 二、决策树

1. **你是否只在 IDE 里写代码？**
   - 否（要跑脚本 / 批处理 / 自建应用 / CI）→ **Token Plan**
   - 是 → 下一题
2. **使用频率多高？**
   - 每天数小时 → **Coding Plan**
   - 偶尔用 → **Token Plan**（别为用不上的额度付月费）
3. **要不要保留跨厂商切换能力？**
   - 要 → **Token Plan**（见下一节）
   - 无所谓 → Coding Plan

## 三、⚠️ 关键权衡：套餐会锁死你的模型自由度

这是最容易被忽略的一点：

> **买了某家的 Coding Plan，你就只能在它内部选模型了。**

跨厂商选型依赖的是"随时能换到最便宜的够用模型"。一旦被 Coding Plan 绑死，这套方法对你只剩「该厂商内部三档」可用。

而厂商**内部**档位价差通常只有 5–20 倍；
**跨厂商**档位价差可以达到 **240 倍**（见 `rules/models.md`）。

**所以正确顺序是：**

1. 先决定「我要不要保留跨厂商能力」
2. 再决定买哪种套餐

而不是反过来 —— 先买了套餐，再发现自己的省钱空间被自己锁死了。

## 四、怎么算（别抄数字，价格每月都在变）

不要记任何具体价格，用这个方法自己算：

1. 估出每月**输出 token 量**（`/cost`、`/usage` 或厂商控制台可查）
2. 套用目标模型的**输出单价**（输入通常便宜得多，且常被缓存打折）
3. 得出月度 API 花费，与套餐月费对比
4. 高于套餐月费 → 套餐划算；低于 → 按量划算

**两个隐性成本别漏掉：**

- 订阅制有**速率上限**（如滚动 5 小时窗口），重度使用会被限流打断
- 按量制没有上限，但**账单不可预测**，务必自己设配额告警

## 五、一句话结论

| 你的情况 | 选择 |
| --- | --- |
| 天天在 IDE 里写，且只在一家生态内 | Coding Plan |
| 要跑脚本 / 批处理 / 自建应用 | Token Plan |
| 想保留跨厂商省钱能力 | Token Plan |
| 用量不稳定或刚开始用 | Token Plan |
