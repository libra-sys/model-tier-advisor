# 任务档位打分表 · L1（按需加载，约 400 token）

四维度各打 1–3 分，求和定档。
**判断依据只取任务描述本身，不要为了打分去读代码库或探索上下文** —— 那会烧掉比省下更多的 token。

## 打分维度

| 维度 | 1 分 | 2 分 | 3 分 |
| --- | --- | --- | --- |
| 推理深度 | 模板化、机械执行 | 标准逻辑，有明确解法 | 架构权衡、多解抉择、需创造性 |
| 影响范围 | 单处（单文件 / 单函数） | 多文件但同模块 | 跨模块 / 跨系统 / 跨服务 |
| 出错代价 | 可一键重来 | 功能受损，需返工 | 数据 / 资金 / 安全，不可逆 |
| 需求明确度 | 明确，照做即可 | 部分模糊，需少量推断 | 模糊，需自行决策与取舍 |

## 定档

| 总分 | 档位 | 含义 |
| --- | --- | --- |
| 4–6 | **轻档 T1** | 经济模型即可，旗舰模型属于浪费 |
| 7–9 | **中档 T2** | 主流模型的舒适区 |
| 10–12 | **重档 T3** | 需要旗舰推理能力，小模型易翻车 |

## 典型任务速查

- **轻档**：格式化代码、改变量名、补注释、查 API 用法、翻译文档、写一次性脚本、批量重命名、提取文本
- **中档**：多文件功能开发、单模块重构、修已知位置的 bug、写单元测试、常规代码审查、写技术文档
- **重档**：系统架构设计、跨服务故障排查、性能优化、安全审计、数据库迁移方案、需求模糊需先澄清、多方案权衡

## 微调规则（±1 档）

- 涉及**陌生技术栈或不熟悉领域** → 上浮 1 档（小模型更容易想当然）
- 有**测试 / 编译 / 类型检查可自动验证** → 可下调 1 档（错了能马上发现，试错成本低）
- **判不准** → 默认中档，不纠结

## 边界原则

1. 档位是**建议**不是指令。判错不纠偏、不回头改、不打断流程。
2. 打分发生在**动手之前**，用 10 秒完成，不要演变成一场分析。
3. 一个会话内若已提示过一次，后续任务默认不再提示。
4. 用户说「直接做」「别提了」→ 本会话彻底关闭提示。
