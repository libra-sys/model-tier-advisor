## 一、先定门槛，再对号入座（这部分不会过期）

- **T1 轻档门槛**：指令遵循稳定、格式输出可靠、单步即可完成。绝大多数当代模型都能满足。
- **T2 中档门槛**：跨文件保持一致、理解项目上下文、产出可直接运行的代码。
- **T3 重档门槛**：长程推理不漂移、能做架构权衡、能发现隐蔽缺陷（并发、边界、安全）。

门槛是稳定的，模型名单是易变的。**任何时候都可以只报档位、不报模型名。**

## 三、什么时候不要听档位

档位只解决"能力够不够"。以下情况，其他因素优先级更高：

| 约束 | 优先看 |
| --- | --- |
| 上下文 > 500K | 上下文窗口，不看档位 |
| 数据不能出境 / 要私有化 | 开源权重（DeepSeek / Qwen / Kimi / GLM） |
| 中文创作、国内业务语境 | 国产模型，往往优于同价海外模型 |
| 交互频繁、要低延迟 | 输出速度（tok/s），不看档位 |
| 需要多模态输入 | 原生多模态模型 |

## 四、使用规则

1. 档位定的是**能力下限**，不是"越便宜越好"。拿不准就往上靠一档。
2. 表外模型按**未知**处理，不猜它的档位。
3. 用户锁定单一厂商时（如只买了一家套餐），只在该厂商内部做档位推荐，不要推荐他拿不到的模型。
4. 本表过期后：只报档位（T1/T2/T3），并提示用户更新 `rules/models.md`。
