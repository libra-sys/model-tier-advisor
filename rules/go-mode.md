# 全自动模式（go / auto / YOLO）下的档位机制 · L3（按需加载，约 920 token）

> 背景：L0 的前提是"人在 GUI 里手动选模型，所以只提示人"。但 agent 处于全自动模式时，人不会实时读提示 —— 此时"提示人不干预"失效，必须换一套机制。

## 什么叫全自动模式

- 你给一个目标，agent 自己跑到完成，中间不请求逐步批准。
- 各家叫法：Claude Code = Auto Mode，Codex = `--full-auto`，Kimi = `--yolo`，圈内统称 YOLO。
- 它与 Plan Mode（只规划不执行）、Default/Accept-edits（每步确认）是同一信任谱的三档。

## 机制切换：从「提示人」到「自动路由」

| | 交互模式（人在） | 全自动模式（go） |
| --- | --- | --- |
| 档位判定 | 同 L1 打分 | 同 L1 打分，不变 |
| 判完做什么 | 一行提示建议换档，然后照常干活 | 把子任务派给对应档位的 subagent，而非提示人 |

为什么：go 模式下没有"人"会看提示，提示等于噪音。但 agent 本身能决定用哪个 subagent / 子模型，所以把"建议"变成"动作"。

## 做法

1. **先判断是否在 go 模式**：特征是"没有逐步确认、输出直接落地"。不确定就当交互模式处理（更保守）。
2. **对每个子任务单独打档**（L1），不要对整个大目标打一个档 —— 子任务难度差异很大。
3. **按档派发**（模型名见 `rules/models.md`，过期只报档位）：
   - T1 子任务 → 经济档 subagent（DeepSeek V4 Flash / GLM-5.3-Flash / Gemini 3.7 Flash）
   - T2 子任务 → 主流档 subagent（DeepSeek-V4-Pro / Qwen3.8 Max / Claude Sonnet 5）
   - T3 子任务 → 旗舰档 subagent（Claude Opus 5 / GPT-5.6 Sol / Kimi K3）
4. **主 agent 负责拆解、派发、汇总、校验**；它自己不必是旗舰 —— 轻量主 agent + 按需派发可显著降本。
5. **危险动作仍上提**：删除、外发、不可逆操作，不因"全自动"就跳过护栏。

## 边界

- 这套机制只在"能切换 subagent / 指定子模型"的工具里有效。纯单模型对话不支持子 agent 时，go 模式下只能退回"提示人，用户事后看"。
- **不要为了省钱把 T3 任务塞给 T1 subagent** —— 这正是返工最贵的浪费。
- 主 agent 拆解质量决定一切：拆得粗，档位判断就失去意义。
